# Modern Missed Scheduled Posts Publisher

Публикует запланированные записи, которые WordPress пропустил: их время
наступило, а статус так и остался `future`.

Версия 1.1.0. Требуется WordPress 7.0+, PHP 8.4+.

## Зачем

Запланированную запись публикует WP-Cron — отложенное событие WordPress.
Если cron на сайте не срабатывает (низкий трафик, отключённый `DISABLE_WP_CRON`,
блокировка loopback-запросов хостингом, WAF или Basic Auth), запись остаётся
в статусе «Запланировано» и после наступления своего времени. Плагин находит
такие записи и публикует их.

Плагин не заменяет WP-Cron и не отключает его: если cron работает штатно,
записи выходят как обычно, а плагин просто не находит пропущенного.

## Как это работает

### Два триггера

Публикацию может запустить один из двух путей; на конкретном запросе работает
один из них.

1. **Браузерный скрипт — основной путь для страниц сайта.** Когда запуск
   назрел, на HTML-странице подключается маленький скрипт, который отправляет
   запрос из браузера посетителя. Скрипт ничего не показывает и не меняет на
   странице; ошибки он молча игнорирует.
2. **Loopback-запрос.** На запросах, где браузерный скрипт не подключается
   (админка, ленты, `robots.txt`, REST и т. п.), на завершении запроса
   (`shutdown`) сайт отправляет неблокирующий HTTP-запрос сам себе на
   `admin-ajax.php`. Ответ не ждётся, посетитель его не замечает.

Если хостинг блокирует loopback-запросы, браузерный скрипт на обычных
страницах всё равно сработает.

Перед подключением браузерного скрипта плагин просит кэширующий слой не
отдавать страницу из кэша (см. «Кэш страниц»).

### Что считается пропущенной записью

Запись со статусом `future` (Запланировано), у которой `post_date` уже
наступил по локальному времени сайта. Плагин берёт такие записи в порядке
времени публикации — от старых к новым.

Плагин не трогает черновики, записи в статусах «На утверждении»,
«Приватная», «Ожидает», а также записи, время которых ещё не наступило.
Опубликовать «на будущее» или изменить содержимое записи он не может.

### Периодичность и лимит

- За один запуск публикуется не больше **20** записей.
- Если пропущенных больше 20, следующий запуск разрешается сразу — плагин
  догоняет бэклог порциями по 20.
- Иначе следующий запуск — не раньше чем через **15 минут** после текущего.
- Частоту можно изменить фильтром (в секундах, минимум 60):

```php
// Проверять пропущенные записи раз в 5 минут.
add_filter(
    'modern_missed_scheduled_posts_publisher_frequency',
    static fn(): int => 300
);
```

### Кэш страниц

Пока плагин ждёт возможности запуститься (прошло больше 15 минут с прошлого
запуска), HTML-страницы отдаются с заголовками «не кэшировать». Это нужно,
чтобы браузерный fallback попал на страницу: из кэша скрипт не выполнится.
Как только запуск произошёл, страницы снова кэшируются.

Ленты, `robots.txt`, trackback, sitemap, REST и JSON-ответы не затрагиваются —
там браузерный скрипт всё равно не выполняется.

## Публичный триггер: что он может и чего не может

Эндпоинт `admin-ajax.php?action=modern_missed_scheduled_posts_publisher`
доступен **анонимно**. Это осознанное решение, а не недосмотр.

**Почему.** Loopback-запрос и браузер посетителя не имеют пользователя и
сессии WordPress. Плагин не может потребовать `manage_options` или обычный
nonce WordPress: у анонимного запроса их нет. Поэтому используется собственный
nonce на солях сайта, и он печатается в HTML страницы — иначе браузер не смог
бы отправить запрос.

**Следствие.** Nonce не является секретом и не защищает от того, кто прочитал
страницу. Он отсекает только слепых ботов и сторонние формы. Любой, кто
прочитал nonce, может вызвать эндпоинт.

**Что это даёт злоумышленнику.** Только одно: возможность выбрать момент
публикации записи, время которой **уже наступило**. Нельзя опубликовать
запись раньше срока, нельзя опубликовать черновик или запись в другом статусе,
нельзя получить содержимое записи или данные сайта. Ответ эндпоинта всегда
`{"success":true}` и не содержит данных.

**Ограничения.** За один запуск — не больше 20 записей; обычно не чаще раза
в 15 минут. Побочные эффекты публикации (пинги, уведомления, рассылки,
вебхуки) — те же, что были бы у WP-Cron для этих же записей.

**Если такой режим не подходит.** Плагин лучше не активировать: отключить
публичный триггер, сохранив при этом работу на хостингах с заблокированным
loopback, нельзя — это его основная функция для таких хостингов. Плагин
рассчитан на сайты, где записи должны выходить по расписанию, а не на сценарии,
где момент публикации критичен для безопасности.

## Установка

1. Скопировать каталог `modern-missed-scheduled-posts-publisher` в
   `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».

Настроек в админке нет, уведомлений плагин не показывает, в базу пишется
только служебная отметка о времени последнего запуска.

## Обновления

Плагин обновляется через штатный механизм WordPress из GitHub:

- источник — релизы и теги репозитория
  [Gnoztis/modern-missed-scheduled-posts-publisher](https://github.com/Gnoztis/modern-missed-scheduled-posts-publisher);
- берётся максимальная версия из релиза и тегов; тег может быть с префиксом
  `v` или без (`v1.1.0` = `1.1.0`);
- архив скачивается только по `https` и только с доменов GitHub;
- в строке плагина есть ссылка «Проверить обновления», которая сбрасывает
  кэш проверки.

Список изменений — в описании релиза на GitHub.

## Требования

- WordPress 7.0 или новее;
- PHP 8.4 или новее;
- MySQL или MariaDB (используется `CAST(... AS UNSIGNED)`);
- исходящие запросы к `api.github.com` нужны только для проверки обновлений.
